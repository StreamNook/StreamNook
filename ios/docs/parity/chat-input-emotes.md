# Parity contract: Chat composer and emotes

Read from StreamNook dev 577f3c02 + working tree of 2026-10-12 (the Android phone shell in `src/mobile`, the shared stores and services in `src`, and the Rust core). Every line is a behavior the iPhone app must match.

Path shorthand used in the citations:

- `m:` is `src/mobile/` (the Android phone shell)
- `s:` is `src/` outside `src/mobile/` (shared stores, services, utils, styles)
- `d:` is desktop code under `src/` consulted for RULE ZERO (usually `src/components/`)
- `r:` is `src-tauri/src/` (the Rust core)
- `k:` is `src-tauri/gen/android/app/src/main/java/app/streamnook/` (the Android Kotlin layer)
- `t:` is `src-tauri/` outside `src/` (config, Android resources)
- `p:` is the repository root
- `pref:` is a file in the StreamNook memory folder (`C:\Users\Brandon\.claude\projects\C--StreamNook\memory\`): Brandon's standing preferences and recorded traps

Units: CSS px map 1:1 to iOS points. Tailwind classes are converted to px (Tailwind spacing unit = 4 px; `text-sm` 14 px, `text-xs` 12 px etc.). Colours as written in the source (hex, rgba, or the CSS variable name).

Legend: `[ ]` not built on iPhone yet; `[x]` seen working on the iPhone; `[~]` built but needs work, OR impossible/replaced on iOS (always with the reason).

Scope: the composer bar under every chat pane on the phone (`m:chat/MobileChatInput.tsx`), its gating (`m:chat/chatGating.ts`, `m:chat/useFollowStatus.ts`), the emote suggestion strip (`m:chat/MobileEmoteCarousel.tsx`), the shared emote / emoji / GIF picker the phone mounts (`s:components/chat/EmotePickerPanel.tsx`), the chat menu sheet (`m:chat/ComposerMenuSheet.tsx`), the command browser (`m:chat/MobileCommandSheet.tsx`), sub-emote owner names (`m:chat/useEmoteOwnerNames.ts`) and the send paths into Rust. Cross-references: the sheet primitive and the keyboard inset are shell-design.md; the message list, tap-to-reply, the long-press fan and mod actions are chat-view.md; the channel points rewards menu is rewards-badges-drops.md; settings rows are settings.md.

## Decisions for Brandon

Not parity lines: open questions found while reading, each to be settled before its screen is built.

- A1. Drafts are one string across all chat tabs on Android (switching tabs carries the text into the next room); desktop keeps one per channel. Recommended for iPhone: per-room drafts like desktop. (m:chat/MobileChatInput.tsx:L113-L113) (d:components/ChatWidget.tsx:L2162-L2171)
- A2. No 500-character counter on Android; desktop shows "N/500". Recommended: the desktop counter.
- A3. No slow-mode countdown on Android; desktop counts down on Send. Recommended: the desktop countdown, driven by Rust's `slow_seconds`.
- A4. Android loses the draft when the Twitch connection is down (send returns nothing but the field clears) and when Twitch drops the message (the field clears; the reason prints in chat); thrown errors keep the draft with no toast. Recommended: keep the draft on any non-success and show the reason.
- A5. Duplicate-message bypass (`chat_input.bypass_duplicate`) is desktop only. Port it (in Rust, at send) or leave it off?
- A6. Rust's standing line ("You can chat as a moderator") and each mode's detail sentence are never shown on the phone (desktop shows them in the hover card). Show them in the chat menu's room-state block?
- A7. Chatter completion inserts the display name, so a localized name mentions nobody; the identity rules say a name is display only. Recommended: insert the login unless the display name differs only by case.
- A8. The phone picker never gets the YouTube flag, so YouTube rooms have no YouTube or 7TV tab. Recommended: pass it like desktop.
- A9. The favorite star is hover-revealed and invisibly tappable on Android. Recommended: long-press context menu on iPhone.
- A10. The command sheet repeats category headers in table order; desktop groups by category. Recommended: desktop grouping.
- A11. On a secondary Twitch tab the points button shows the STREAM's balance while its menu lists the TAB's rewards (rewards-badges-drops.md should decide). (m:chat/MobileChatInput.tsx:L137-L142) (m:chat/MobileChatInput.tsx:L654-L668)
- A12. Several shared commands reach desktop-only listeners and silently do nothing on Android ("/poll", "/prediction", "/clearmessages", "/usercard", "/user"). Build their phone surfaces on iPhone, or mark them desktop-only so the phone toasts "works in the desktop app"?
